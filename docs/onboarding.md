# Administrator-created future hires

On People, choose Invite person and enter the work email, personal contact, employer-local start time, IANA time zone and invitation lead days. The default lead is seven days; the supported range is zero to thirty. Invalid local times and ambiguous daylight-saving times are refused. An existing work email is refused rather than merged. A personal contact never becomes a work sign-in alias, including when it matches another person's work email.

Before dispatch, the administrator records the employer’s authority to use the contact for transactional onboarding and responsibility for required notice and consent. An imported address grants neither mailbox proof nor legal consent. Standing authorization ends when its accountable administrator loses authority. The scheduled maintenance handler sends one activation invitation when the hire enters the lead window, before start. The contact is marked unverified until activation. The link expires after seven days. Its digest, person binding, generation and consumption are durable. Start gates and personal contacts are portable directory state; activation credentials are excluded from archives. Reissue after restore establishes fresh installation custody; the usable link exists only in the message. Reissue invalidates the old link before a replacement is sent. An uncertain transport outcome is recorded without an automatic resend; an administrator must explicitly reissue or retry while the current pre-start window remains open. Each queued initial send, reissue, retry and reminder rechecks the current schedule, rescission and sending authority immediately before transport. Provider-accepted mail may still arrive after start; delivery timing remains unqualified.

Activation permits passkey enrollment with the existing fresh-email and first-factor gates. It does not prove the work address. The hire must prove the work address through ordinary email confirmation before using an application. Auth refuses launcher opens, native SAML assertions, OIDC authorization, token issuance and online token use before the current start time. Moving start later also refuses an already-issued code or online token. Self-contained tokens cannot be recalled from applications that do not check current Auth authority.

People provides Update start time, Reissue activation and Rescind offer. Each requires a hardware administrator session and fresh local email confirmation, rechecked at the write. Rescission revokes local sessions, deletes passkeys, invalidates activation and fences native linked sessions. Maintenance never sends activation after start or rescission. A zero-day lead leaves no pre-start activation window; the hire needs the verified temporary-pass path below. A late hire can be recorded with their actual start time without sending personal activation.

This bounded path supplies no HR-source qualification, live-delivery receipt, automatic reminder or manager escalation, push authenticator, password, downstream provisioning, RADIUS or desktop qualification. These remain in AUTH-ONBOARD-001's Gap.


## Day-one hosted enrollment

Set the hire’s current manager in the directory. From My account, that manager records how they verified the direct report and requests a pass using their own passkey session and fresh email confirmation. Authorized administration or help desk with all required recovery permissions and editable scope over every group of the hire issues the pass from My account. A manager request grants no issuance authority.

Copy the pass from its one-time display and deliver it in person, by phone or through the manager. Only its digest is stored. The native path allows one use within one hour of verification; a replacement revokes the previous pass. Group lifetime policy, reusable first-day passes and desktop login remain unfinished.

The hire chooses Use a temporary access pass on Sign in, confirms the work address in the same browser, then enrolls a passkey. The temporary session permits enrollment only and ends on completion. It cannot launch an app, satisfy app step-up or issue tokens. Current manager, issuer scope, privileged-target protection, rescission and expiry are rechecked on use and enrollment. Application access still follows the current authorized start time.

A proved personal contact may receive credential-free recovery notices only after the employer explicitly enables that option under Record contact authority. The transport rechecks this permission separately from activation; the pre-start activation cutoff grants no recovery authority. Live recipient delivery and the full temporary-pass notification journey remain unproved.
