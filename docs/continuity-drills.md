# Continuity drills

Keep a separate backup administrator on a protected emergency mailbox outside the employer’s required upstream domain. Enroll two independent hardware keys for that administrator and the owner, keeping a spare in separate custody. Ordinary accounts cannot change the upstream requirement or redeem the local owner recovery token. Neither an outage nor a drill changes those gates. The security owner subscribes its authorized receiver to recovery events through the existing signed event door. The drill configures that receiver explicitly, loses it across restart, then verifies its signed, credential-free delivery and cursor recovery. Affected employees receive durable notices and email for approval, cancellation, completion and local emergency use.

The `Continuity drills` workflow rehearses a temporary root installation every Monday at 03:17 UTC, and can be dispatched manually. It uses synthetic identities and no held provider accounts. Run the same rehearsal after a production build with `pnpm run drill:continuity`. It never connects to a production issuer. The TAP artifact records failed steps and explicitly unmeasured boundaries; a setup failure is not a passing drill.

The rehearsal measures lost redundant factors, a distinct higher-ranked recovery approver, cancellation after approval, notices across restart, old-factor and token replay, required-upstream failure, authorized upstream-policy recovery, replacement of a genuinely expired SAML signer, and connector retry/read-back without duplicate accounts. The real CLI exports, resets and imports an owner installation with separately held private configuration; the archive cannot restore live sessions, an old emergency token or signing secrets. The owner redeems a new local token and enrolls replacement hardware before administration resumes.

The independent SAML relying-party test edge validates actual XML signatures and enforces its configured X.509 validity dates. It refuses the aged certificate before replacement and accepts the replacement signer; old trust alone cannot validate the new signer. This is a strict test-edge profile, not a claim that every vendor enforces certificate dates. Each vendor’s own configuration belongs to its catalog qualification.

This is root-installation continuity. Isolated-employer owner-authorized inactive restoration remains AUTH-TRANSFER-002, and hosted issuer disaster recovery remains AUTH-OPS-001. The existing local owner emergency token remains AUTH-IDENTITY-001’s exceptional gate; this drill adds no independent approval policy to it. The separately protected backup administrator and redundant factors use existing role, hardware and fresh-email gates. No new emergency permission, upstream bypass or automatic production action is introduced.
